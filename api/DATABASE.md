# Base de datos de Adoptly

Esta guia explica como preparar la base local para el backend. El proyecto usa PostgreSQL y Sequelize 6. El servidor comprueba la conexion al iniciar, pero no crea ni cambia tablas por si solo: no se llama a `sequelize.sync()`.

## Configuracion

Copia `.env.example` a `.env` y configura tus datos locales:

| Variable | Uso | Ejemplo local |
| --- | --- | --- |
| `DB_HOST` | Servidor PostgreSQL | `localhost` |
| `DB_PORT` | Puerto PostgreSQL | `5433` |
| `DB_NAME` | Nombre de la base | `adoptly` |
| `DB_USER` | Usuario PostgreSQL | `postgres` |
| `DB_PASSWORD` | Contraseña local | Completar localmente |
| `JWT_SECRET` | Clave local para firmar tokens | Generar una clave aleatoria de 32 bytes |

No compartas `.env` ni claves reales. El backend exige que `JWT_SECRET` tenga al menos 32 caracteres.

## Preparar tablas

En pgAdmin (Query Tool conectado a la base `adoptly`) o `psql`, ejecuta el SQL de abajo en este orden. Si ya existe `Mascota`, no vuelvas a crearla: ejecuta solamente el SQL de `Usuario` y el `ALTER TABLE` para agregar la clave foranea.

```sql
CREATE TABLE IF NOT EXISTS "Usuario" (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  nombre_completo VARCHAR(150) NOT NULL,
  email VARCHAR(254) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  telefono VARCHAR(30),
  rol VARCHAR(20) NOT NULL CHECK (rol IN ('administrador', 'publicador', 'adoptante')),
  tipo_publicador VARCHAR(20) CHECK (tipo_publicador IN ('refugio', 'rescatista', 'particular')),
  descripcion TEXT,
  activo BOOLEAN NOT NULL DEFAULT TRUE,
  "createdAt" TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  "updatedAt" TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT usuario_tipo_publicador_rol CHECK (
    (rol = 'publicador' AND tipo_publicador IS NOT NULL)
    OR (rol <> 'publicador' AND tipo_publicador IS NULL)
  )
);

CREATE TABLE IF NOT EXISTS "Mascota" (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  publicador_id INTEGER NOT NULL,
  nombre VARCHAR(100) NOT NULL,
  especie VARCHAR(20) NOT NULL CHECK (especie IN ('perro', 'gato')),
  raza VARCHAR(100),
  tamanio VARCHAR(20) NOT NULL CHECK (tamanio IN ('pequenio', 'mediano', 'grande')),
  fecha_nacimiento DATE,
  descripcion TEXT NOT NULL,
  provincia VARCHAR(100) NOT NULL,
  localidad VARCHAR(100) NOT NULL,
  estado_adopcion VARCHAR(30) NOT NULL DEFAULT 'disponible'
    CHECK (estado_adopcion IN ('disponible', 'con_solicitudes_pendientes', 'adoptada')),
  activa BOOLEAN NOT NULL DEFAULT TRUE,
  "createdAt" TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  "updatedAt" TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

ALTER TABLE "Mascota" ADD CONSTRAINT mascota_publicador_id_fkey
  FOREIGN KEY (publicador_id) REFERENCES "Usuario"(id);
```

`CREATE TABLE IF NOT EXISTS` no reemplaza tablas existentes. Si ya agregaste la clave foranea, omite el `ALTER TABLE` para evitar que PostgreSQL avise que el constraint ya existe.

## Tablas y reglas

### `Usuario`

Guarda el perfil y la cuenta. Los roles son `administrador`, `publicador` y `adoptante`; el registro público solo acepta publicador o adoptante. Un publicador debe indicar `tipo_publicador` (`refugio`, `rescatista` o `particular`). Email se normaliza a minúsculas y es único. `password_hash` guarda un hash bcrypt, nunca la contraseña ni el hash se devuelve por la API. Las cuentas desactivadas no pueden iniciar sesión ni usar rutas privadas.

### `Mascota`

Cada registro apunta a `Usuario.id` mediante `publicador_id`. Solo publicadores pueden publicar; solo el dueño puede editar o desactivar su registro. Desactivar cambia `activa` a `false`, sin borrar la fila. Los endpoints públicos muestran únicamente mascotas activas de publicadores activos.

## Migraciones, seeds y tests

Para este trabajo se pueden crear archivos locales en `migrations/`, `seeders/` o `tests/`. Por el acuerdo del proyecto, `.gitignore` los excluye de GitHub; por eso, el SQL de preparación necesario para colaboradores debe seguir documentado en este archivo. No uses `DROP TABLE` ni sincronización destructiva.
